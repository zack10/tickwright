# implode crashes jq on input that is not a list of valid codepoints

`implode` aborts the whole process with an assertion failure (core dump) when its input is not an array of numbers:

```
$ jq implode <<< '[{"key": "x","value": 0}]'
jq: jv.c:717: jv_string_implode: Assertion `jv_get_kind(n) == JV_KIND_NUMBER' failed.
Aborted (core dumped)
```

Expected: `implode` never crashes. Wrong input is an ordinary jq error that `try` can catch, and every number is turned into a character:

- input that is not an array fails with `implode input must be an array`
- an element that is not a number fails with `<type> (<value>) can't be imploded, unicode codepoint needs to be numeric`, for example `string ("a") can't be imploded, unicode codepoint needs to be numeric`
- a number that is not an integer is rounded down (1.9 is codepoint 1)
- a number outside the Unicode range (below 0 or above 1114111), or a UTF-16 surrogate (55296 to 57343), becomes the replacement character U+FFFD (65533)

Examples (`filter`, input, output):

```
implode|explode            [-1,0,1,2,3,1114111,1114112,55295,55296,57343,57344,1.1,1.9]   -> [65533,0,1,2,3,1114111,65533,55295,65533,65533,57344,1,1]
map(try implode catch .)   [123,["a"],[nan]]   -> ["implode input must be an array","string (\"a\") can't be imploded, unicode codepoint needs to be numeric","number (null) can't be imploded, unicode codepoint needs to be numeric"]
```
