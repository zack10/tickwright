# Phase 4 gate, 2026-11-17 to 18

The gate run agreed on 2026-11-17 (roadmap, "The gate run"): model `gpt-5.6-luna`, one run at a time, 10 runs per ticket, prompts plan.v5, agent.v7, triage.v1, analyze.v2, planner.v3, discover.v3, reviewer.v7 (no agent code changed since PR #35). Bar fixed before the run: on every ticket at least 7 of 10 correct and at most 1 wrong; on every project at least 80% of its runs correct; over the gate at most 6 wrong fixes shipped. Stop rule per ticket: 2 wrong fixes shipped, or the first 4 graded runs all failing. Cap $25.

**Result: the gate is not passed.** 188 counted runs: 159 correct, 6 wrong fixes shipped, 20 blocked, 3 infrastructure failures. $11.43 for the gate's own runs, plus $0.75 for fd-590 and dayjs-589 (list A item 5, counted here as agreed).

## Infrastructure found during the gate

- **The daily token limit stopped the gate** (2026-11-17 22:43 UTC). `LLM_DAILY_TOKEN_LIMIT` was 80M; the gate uses about 130M tokens (most of it cached input). 9 catch2-2288 runs were lost. Raised to 150M in `.env.prod` with the user's approval.
- **The app recreated from Windows PowerShell lost its data mount.** `/home/zack/agent-data` resolved inside Docker Desktop's own 2.9 GB disk, the free-disk check (`EXECUTION_MIN_FREE_DISK_GB`) failed the next run, and stored diffs were not visible. Recreated from WSL; 1 run lost. The production stack must be run from WSL only (CLAUDE.md, docs/guides/PRODUCTION_RUN.md).
- **The OpenAI account ran out of credits** (2026-11-18 02:06 UTC): every call failed with 429 within seconds, so 16 jq runs were recorded as infrastructure failures in four minutes and the eval moved on to the next ticket. Rerun after the user added credits. Nothing warns before the balance runs out, and a run of 16 identical failures does not stop the batch (limitation 54).
- **A database error is returned without a trace** (limitation 59, new): `handlePrismaError` (`src/middleware/errorHandler.ts`) turns every Prisma code it does not name into `500 DATABASE_ERROR` and logs nothing, so the cause of fd's three failures is unknown. The eval treats one failed status request as the end of the run.
- **The guard's per-ticket caps** were set from earlier runs; jq-2624's two long declined runs reached its cap one run early.
- Cost estimate checked: the database's token counts at the launcher's prices give $10.63 for the gate's first 22 hours, the same as the guard's figure.

## What the gate shows

- **Every wrong fix comes from agent quality, and five of six from one gap**: the fix, and the agent's tests, cover the example the ticket names and not the rest of what the change touches (limitation 47; jq-2821 is the near case of an example left untested, 33). The reviewer passed all six.
- **Most of the other misses are blocked runs, the safe outcome.** jq's 16 blocked runs come from the environment (limitation 35, 9 runs), existing tests that the change makes outdated (31, 4 runs, a Phase 6 row), the agent declining a fix it could not finish (2) and the file limit (1). catch2's four come from 31 and the step limit.
- **gson, dayjs and fd are solid on this model**: 107 of 110 counted runs correct, 0 wrong, the 3 others infrastructure.
- Not shown: whether a stronger model avoids the row 47 fixes (limitation 22, untested); fd's runs all used the unconfirmed environment (row 35 (a), item 5), so fd's result rests on the agent's own test.
